## О проекте:
Web-приложение объединяет в одной системе три уровня пользователя: управляющая компания, жильцы и подрядчики.

Платформа закрывает основные операционные циклы УК и жителей:
- УК - заявки, начисления, голосования, регуляторные сроки, чаты;
- житель - подача заявок, оплата ЖКУ, передача показаний, голосования, маркетплейс услуг.

## Ключевые возможности.

### Для УК:
- **Дашборд** — 5 KPI-карточек с переходом на детальные списки
- **Приоритетная очередь заявок** — сортировка по приоритету, (быстрое назначение исполнителя (в доработке))
- **Сборы и долги** — собираемость текущего месяца, тренд за 9 месяцев, топ-должников
> Регуляторные сроки — лифты, газ, пожарка, дымоходы с индикацией (в доработке)
- **Голосования** — создание с рассылкой push, контроль кворума, (формирование протоколов (в доработке))
> Дома и квартиры — реестр объектов, лицевых счетов, индивидуальные счётчики (в доработке)
- **Чат и обращения** — единая входная точка для коммуникации с жильцами
> Аналитика и отчёты — выгрузка для ГИС ЖКХ, ГЖИ (в доработке)
- **Мультиарендность** — каждая УК видит только свои дома, заявки и данные
- **Профиль** — редактирование данных, смена email и пароля

### Для жителя:
- **Подача заявок** — категория, фото, отслеживание статуса
> Оплата ЖКУ — квитанции, история, СБП / СберPay (в доработке)
> Передача показаний — ИПУ электричество / вода / газ (в доработке)
> Голосования — участие в голосованиях, контроль кворума
- **Чаты** — с диспетчером УК, с соседями, в группах подъезда (в доработке)
- **Маркетплейс** — клининг, ремонт, доставка от проверенных подрядчиков
- **Профиль** — данные квартиры, аватар, смена email и пароля

## Технологический стек:
- **Frontend** - React 19, TypeScript 5, Vite 7, React Router, Sonner, lucide-react;
- **Backend** - .NET 10, ASP.NET Core, Entity Framework Core, FluentValidation, JWT-аутентификация;
- **База данных** - PostgreSQL 16;
- **Realtime уведомления** - SignalR;
- **API** - REST с JSON, OpenAPI / Swagger в dev-режиме;
- **Архитектура** - Domain -- Application -- Infrastructure -- Api.

## Старт приложения.

### Требования:
Для локального запуска необходимы:

- **Node.js** 20+
- **.NET SDK** 10+
- **PostgreSQL** 16+

### 1. Запуск frontend:

```bash
cd web
npm install
npm run dev
```

Переменные окружения (`web/.env`):
> VITE_API_URL=http://localhost:5211/api

### 2. Запуск backend:

```bash
cd backend
dotnet restore
dotnet run --project MyHome.Api
```

> Swagger UI доступен на `http://localhost:5211/swagger`

-----
Локальные тонкости (строка подключения и JWT-ключ) **не хранятся в репозитории**.
Их нужно задать одним из способов:

1. Локальный файл `appsettings.Development.json` (в `.gitignore`), либо
2. Переменные окружения (`ConnectionStrings__DefaultConnection`, `Jwt__Key`), либо
3. `dotnet user-secrets`.

`Jwt__Key` должен быть длиной минимум 32 байта — приложение падает на старте,
если ключ короче. Чтобы сгенерировать сильный ключ: `openssl rand -base64 64`.

Конкретные параметры подключения, порты, имя БД и т.п. — спрашивать у владельца проекта.

## 🗃 Модель данных (основные сущности)

> Модель данных планируется пересмотреть и сделать более грамотной. Планируется пересмотр отдельных связей между сущностями и механизмов привязки пользователей к объектам ЖК.

| Сущность | Назначение |
|---|---|
| `Organization` | Управляющая компания |
| `User` | Жильцы и сотрудники УК (поле `Role` решает распеределение между уровнями пользователей и принадлежит к `OrganizationId`) |
| `Building` | Дома в реестре УК (жильцы привязаны к УК по совпадению введённого адреса в профиле) |
| `Apartment` | Квартиры с привязкой к жильцу |
| `ServiceRequest` | Заявки (для УК от жителей) |
| `UtilityBill` | Начисления ЖКУ |
| `MeterReading` | Показания счётчиков |
| `AutoPaymentSetting` | Настройки автоплатежа жителя |
| `Poll` + `PollOption` + `PollVote` | Голосования и опросы |
| `Chat` + `ChatMessage` + `ChatMember` + `MessageReaction` | Чаты с реакциями и реплаями |
| `ComplianceDeadline` | Регуляторные сроки (лифт, газ, пожарка, дымоходы) |
| `Notification` | Уведомления внутри приложения |
| `Service` + `ServiceOrder` + `ServiceReview` | Маркетплейс услуг |
| `NewsPost` + `NewsAttachment` + `NewsComment` | Объявления УК |
| `UserSettings` + `DeviceSession` | Настройки и активные сессии пользователя |
| `Expense` | Внутренние расходы УК |
| `SupportTicket` | Обращения в поддержку платформы |

## Аутентификация:
- **JWT Bearer** для REST-вызовов (заголовок `Authorization: Bearer <token>`)
- **Query-token** для SignalR (`?access_token=...`)
- Роли в claim: `Manager` (УК) и `Resident` (житель)
- Защита маршрутов на фронте: `<ManagerRoute>` и `<PrivateRoute>` в `web/src/app/App.tsx`
